## Production-bounded geography

Legislative geography supports two explicit scopes:

- `INTERNAL_REVIEW` — the existing non-release preview contract;
- `PRODUCTION_BOUNDED` — a geography-only production declaration that requires explicit geometry governance.

A `PRODUCTION_BOUNDED` group remains `publication_eligible=false` at the geography layer because the polygon resolver supplies geography only, not officeholder publication authority.

The only currently supported production geometry policy is `texas-legislative-geometry-governance/0.1`. Before constructing the resolver, the loader requires the production group to contain exactly the accepted Texas adapter/service/plan tuple:

| Binding | Adapter | District | Plan |
| --- | --- | --- | --- |
| House | `DIST-TX-HOUSE-H2316` | `49` | `PLANH2316` |
| Senate | `DIST-TX-SENATE-S2168` | `14` | `PLANS2168` |

The service URLs must also equal the version-governed Texas service pins. Reusing the Texas policy ID with another service or plan fails closed as `TEXAS_GEOMETRY_GOVERNANCE_BINDING_DRIFT`.

After binding validation, the loader runs the Texas geometry-version preflight before engine construction or address geocoding. Live marker drift fails as `GEOMETRY_VERSION_DRIFT`.

2. the exact production package archive SHA-256 declared by the proposed catalog entry;

## Readiness receipt

A successful dry run emits `texas-activation-readiness/0.1` with:

- `status=READY_TO_ACTIVATE`;
- hashes for the package, archive, bounded acceptance receipt, proposed catalog entry, proposed legislative group, and deployment evidence;
- PASS dispositions for production profile, public identity, geometry policy binding, production deployment, and inactive-default checks;
- `activation_authorized=false`;
- `repository_activation=NOT_ACTIVATED`;
- `canonical_writes=0`.

`READY_TO_ACTIVATE` therefore means the exact proposal is structurally ready for a separate explicit activation decision. It is not itself activation authorization.
